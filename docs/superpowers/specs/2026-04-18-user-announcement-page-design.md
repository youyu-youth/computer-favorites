# 用户端系统公告页设计文档

## 1. 背景
- 当前项目已具备管理端公告管理的模块规划，但用户端缺少一个独立、可沉浸阅读的系统公告展示页。
- 用户提供了偏“技术发布日志”风格的参考图，要求保留纵向时间线阅读节奏，并完整展示公告标题与正文内容。
- 本次设计阶段仅覆盖用户端前端页面，数据使用假数据，不接入后端接口。

## 2. 目标
- 新增一个用户端独立公告页，路由建议为 `/computer/announcement`。
- 页面同时满足“系统公告中心”和“技术版本日志”两种阅读诉求。
- 所有公告项必须完整展示 `title` 与 `content`，不允许折叠、摘要省略或截断正文。
- 页面必须支持桌面端与移动端响应式布局，并完整支持明亮/暗黑模式切换。
- 页面需使用 Vue 3 + TypeScript + Tailwind CSS 实现，可使用 PrimeVue `Timeline` 作为结构组件，但禁止使用 PrimeVue 默认样式。

## 3. 非目标
- 本阶段不实现后端接口对接。
- 本阶段不实现公告详情二级页。
- 本阶段不实现全文搜索、分页请求、骨架屏和服务端筛选。
- 本阶段不修改管理端公告模块 spec 与任务清单。

## 4. 参考约束
- 主题主色使用用户端既有主题令牌 `primary600 = #d97706`。
- 主题变量优先复用 `computer-favorites-web/src/theme/user/tokens.ts` 与 `computer-favorites-web/src/theme/user/tokens.css`。
- 页面风格需与用户端现有页面保持一致，遵循 `computer-favorites-web/src/views/user/HomeView.vue`、`computer-favorites-web/src/views/user/MessageCenterView.vue` 的暗黑模式和卡片层次习惯。
- 严禁使用渐变背景，交互强调通过边框、透明度、阴影和主色高亮完成。

## 5. 页面定位
- 页面名称：系统公告
- 页面入口：用户端独立页面
- 推荐路由：`/computer/announcement`
- 推荐视图文件：`computer-favorites-web/src/views/user/AnnouncementView.vue`

## 6. 页面信息架构
页面分为四个连续阅读区块：

1. 顶部概览区
2. 筛选与状态区
3. 置顶公告区
4. 时间线正文区

### 6.1 顶部概览区
- 展示页面标题“系统公告”。
- 展示辅助说明文案，例如“按发布时间查看平台功能更新、问题修复与系统变更”。
- 展示轻量统计信息：
  - 公告总数
  - 当前展示类型
  - 最近发布时间
- 该区域承担页面识别和信息概览，不承载复杂操作。

### 6.2 筛选与状态区
- 提供类型筛选：
  - 全部
  - 新增内容
  - Bug 修复
  - 系统更新
- 提供“仅看置顶”切换能力。
- 展示当前结果数量。
- 桌面端表现为横向工具条；移动端改为可横向滚动的按钮组与紧凑状态条。

### 6.3 置顶公告区
- 展示 `is_top = 1` 且 `status = 1` 的公告。
- 每条置顶公告仍完整展示标题和正文，不做摘要。
- 视觉上采用更强的主色边框、标签或标记点，但不脱离整体克制风格。
- 置顶区的作用是帮助用户优先阅读重点公告，而不是替代时间线主内容。

### 6.4 时间线正文区
- 按发布时间倒序展示所有可见公告。
- 使用纵向时间线组织阅读顺序，视觉结构接近参考图。
- 每个时间线节点右侧展示完整公告卡片，包含：
  - 标题
  - 类型标签
  - 发布时间
  - 置顶标记（如适用）
  - 正文全文

## 7. 数据模型
### 7.1 数据来源
- 页面初期使用本地假数据，字段结构对齐 `t_announcement` 表。

### 7.2 字段定义
建议前端假数据字段如下：

```ts
interface AnnouncementItem {
  id: number
  title: string
  content: string
  type: 1 | 2 | 3
  isTop: 0 | 1
  status: 0 | 1
  publishTime: string | null
  createTime: string
  updateTime: string
}
```

### 7.3 视图映射字段
为简化模板渲染，建议映射出以下视图字段：

```ts
interface AnnouncementViewItem extends AnnouncementItem {
  typeLabel: string
  typeTone: 'feature' | 'bugfix' | 'system'
  isVisible: boolean
  displayDate: string
  displayTime: string
  sortTime: string
}
```

### 7.4 映射规则
- `type = 1` -> `新增内容`
- `type = 2` -> `Bug 修复`
- `type = 3` -> `系统更新`
- `status = 1` 视为可展示
- `publishTime` 优先作为展示时间
- 当 `publishTime` 为空时，回退使用 `createTime`
- 列表按 `sortTime desc` 排序

## 8. 组件拆分
### 8.1 页面组件
- `AnnouncementView.vue`
  - 负责页面布局、假数据加载、筛选状态管理、列表分组和组合渲染。

### 8.2 展示组件
- `AnnouncementHero.vue`
  - 展示页面标题、副标题和统计信息。
- `AnnouncementFilterBar.vue`
  - 展示类型筛选、置顶切换和结果数。
- `AnnouncementPinnedList.vue`
  - 展示置顶公告列表。
- `AnnouncementTimeline.vue`
  - 封装 PrimeVue `Timeline`，统一时间线结构与主题化样式。
- `AnnouncementTimelineItem.vue`
  - 展示单条公告的标题、标签、发布时间和正文全文。

### 8.3 数据文件
- `announcement.mock.ts`
  - 存储假数据。
- `announcement.ts` 或页面内本地常量
  - 存储类型映射、排序工具和格式化逻辑。

## 9. 视觉设计
### 9.1 颜色
- 主强调色：`#d97706`
- 亮色模式下：
  - 页面底色使用用户端浅色页面背景变量
  - 卡片底色使用用户端卡片背景变量
  - 重点标题、节点、标签边框使用主色
- 暗黑模式下：
  - 页面背景使用 `darkBg`
  - 卡片背景使用 `darkCard`
  - 时间线连接线和普通边框使用较低对比度深灰
  - 主色仅用于焦点、标签、关键标题和时间节点

### 9.2 卡片
- 公告卡片使用圆角、中等阴影、细边框建立层次。
- 卡片头部重点展示标题、类型、发布时间。
- 正文使用更舒适的行高和段落间距，保留换行。

### 9.3 时间线
- 左侧时间线列宽在桌面端固定，突出“发布日期锚点”。
- 时间线节点使用主色圆点，连接线使用低对比度细线。
- 在移动端收缩为单列后，时间节点移动到卡片上方，仍保留线性阅读关系。

## 10. 交互设计
- 类型筛选切换后立即在前端内存数据中筛选。
- “仅看置顶”开启后，只保留置顶公告列表和时间线中的置顶项。
- 悬停态只允许轻微边框高亮、背景透明度变化和阴影提升。
- 所有可点击元素必须带 `cursor-pointer`。
- 不使用复杂动画，推荐仅使用项目已有过渡时长变量。

## 11. 响应式设计
### 11.1 桌面端
- 使用“左侧时间线 + 右侧正文卡片”的双列阅读布局。
- 顶部概览区与筛选区横向展开。

### 11.2 平板端
- 缩窄时间线列宽，保留时间轴与正文并行。
- 置顶区切换为单列卡片列表。

### 11.3 移动端
- 页面整体切换为单列布局。
- 筛选区改为横向滚动 chips。
- 时间点移动到公告卡片上方，正文卡片全宽展示。
- 外边距收窄，但保留正文行高和段落留白，优先保证阅读性。

## 12. 明暗模式设计
- 页面不得依赖单独的静态配色文件，优先复用用户端主题变量。
- 明亮模式强调清晰分层和暖色聚焦。
- 暗黑模式强调低对比背景和可读性文本，避免大面积高亮橙色。
- 同一组件必须在两种模式下保持相同的信息结构和交互位置。

## 13. PrimeVue 使用策略
- 仅使用 PrimeVue `Timeline` 的结构能力。
- 使用 `pt`、插槽和自定义 class 覆盖所有默认视觉样式。
- 不允许出现 PrimeVue 默认 marker、默认 spacing 和默认主题色残留。

## 14. 假数据建议
- 至少提供 8 到 12 条公告，覆盖三种类型。
- 至少包含 2 条置顶公告。
- 至少包含 2 条长正文公告，用于验证完整展示与移动端阅读体验。
- 时间分布建议覆盖“最近更新”和“较早更新”，便于验证时间线层次。

## 15. 实现建议
- 优先创建组件目录 `computer-favorites-web/src/components/user/announcement/`
- 优先使用 `@/` 别名导入。
- 组件采用 Vue 3 Composition API + TypeScript。
- 样式全部使用 Tailwind CSS 与主题变量，不写独立的 PrimeVue 视觉补丁文件。
- 如果页面逻辑超过单文件可维护范围，再拆出 `useAnnouncementPage.ts`。

## 16. 验收标准
- 存在独立的用户端系统公告页面。
- 页面完整展示假数据中的公告标题和正文内容。
- 页面具备类型筛选和仅看置顶能力。
- 页面在桌面端、平板端、移动端布局均不破坏阅读体验。
- 页面在明亮模式与暗黑模式下均保持清晰可读。
- 页面主色与重点强调统一为 `#d97706` 体系。
- PrimeVue `Timeline` 已被主题化，页面中不出现其默认样式。

## 17. 风险与注意事项
- 公告正文较长时，若段落样式处理不当，移动端会出现阅读疲劳。
- 如果置顶区与时间线同时展示置顶公告，视觉上需通过说明文案避免用户误解为重复数据错误。
- 若直接在单一页面文件中编写全部结构，后续接入真实接口和分页能力时可维护性会下降，因此应优先组件化。

## 18. 后续实现边界
- 当前实现只做前端静态页面与假数据交互。
- 后续接入真实接口时，可在不调整视觉骨架的前提下替换数据源。
- 若后续需要补充公告详情页，应在当前时间线页基础上新增“详情跳转”能力，而不是重做列表结构。
